# Manual smoke test (not automated: needs root, a terminal and a desktop)

1. `python3 scripts/setup_wizard.py`: pick "Every detail" once and check each step lists what it changes; type `?` at a question in "Essentials only". Answer n at the install question and check nothing changed (no `/opt/envh`, no `envh` user), then rerun and install. Choose a vault passphrase; note the console phrase. `ls -l /usr/local/bin/envh` points into `/opt/envh/env`, and `/opt/envh/installed-from` names the commit.
2. Open a separate terminal (not the Claude desktop pane): `sudo envh-console`. Expect: console phrase, passphrase prompt, three ✓ lines, then the full-screen console with "Console ready" in its activity list. `/` lists the commands, `?` the shortcuts; typing letters without `/` shows nothing. Resize the window: the screen redraws to fit.
3. In your own terminal: `envh list` shows no secrets. `cat /var/lib/envh/vault.age` is denied.
4. `envh import --dry-run ~/code/some-project` on a repo with `# Mode` headers; check names and presets; rerun without `--dry-run`, approve on the console, check the plan lists each file's new lines and no values, check the original is in the printed backup folder, then delete that folder.
5. In the console, `/keys`: each value shows only its first and last few characters. F2 renames a key a preset uses, after the passphrase; `envh list` shows the new name in the preset. Open a key, Describe it; `envh list` shows the description. Rename another key: it asks only to confirm now, and the header says how long changes stay unlocked; `/lock` ends that. Show a value: it hides itself after 30 seconds. In `/presets`, add a variable to a preset and press Ctrl-S: the changes are listed before the passphrase. In `/settings`, turn Notifications off and save; `config.yaml` says `notify: false`. Back home, ↑ brings back the last commands.
6. `envh session start <preset> --minutes 30 --reason "smoke"`; approve with the vault passphrase (the prompt shows the console phrase); `envh run --session <id> --reason "smoke" -- env | grep -c KEY`.
7. `envh run --with SOME_SECRET --reason "one-off" -- true`; approve; confirm `audit.jsonl` has request/decision/run lines.
8. At a request, type a wrong passphrase: "Wrong passphrase", typing pauses for two seconds, the request stays, nothing you typed shows on screen, and `audit.jsonl` has a `wrong_passphrase` line. Start a request and press Ctrl-C in its terminal: the card says it was withdrawn and ignores typing until Enter. Send two requests at once: the second appears only after the first is decided. Start typing `/ke` and send a request: it waits, announced on the status line, until Esc.
9. In a Claude Code session with `claude/skills/envh` and the hook installed: ask it to run a script that needs a key; expect the in-app ask, then the console prompt; deny once and confirm the agent stops and explains. Ask it to run `envh list` and `grep -n "envh session start" README.md`: no in-app ask for either.
10. In Cursor, after the wizard's "Connect Cursor" step: ask the agent to run a script that needs a key; expect Cursor's approval prompt with the envh reason, then the console prompt. Ask it to run `envh list` and `ls`; both run as they did before the hook.
11. Edit `~/.claude/skills/envh/SKILL.md` and `~/.cursor/hooks/envh_ask.py`, rerun the wizard: steps 5 and 6 say each is out of date, and answering n leaves "out of date" in the summary.
12. `sudo envh uninstall --dry-run`.
